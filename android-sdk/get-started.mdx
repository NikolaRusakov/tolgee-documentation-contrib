Tolgee delivers Android translations two ways: bundled in the APK with the Tolgee CLI, or over the air through a
Content Delivery read by Tolgee Android SDK. This page is for anyone starting an integration. It settles that choice,
points you at the guide for your UI toolkit, and lists what to prepare in the Tolgee Platform before you change any
code.

## Decide on over-the-air updates

This is the first decision, because it decides whether you add Tolgee Android SDK at all. **Bundled** translations
ship inside the APK: the Tolgee CLI writes them into `res/values-xx/strings.xml` and a corrected text needs a new
release. **Over the air**, a Content Delivery serves the translations at runtime, so a fix reaches installed apps
within minutes. Both keep `strings.xml` in the app as the offline fallback.

A second, independent decision is where the keys themselves come from. The two combine into four paths:

| Keys come from | Bundled in the APK | Over the air |
|---|---|---|
| **`strings.xml` in your repository** | Push with the CLI, translate on the platform, `tolgee pull` before each release | Push with the CLI, the Content Delivery serves JSON, the app reads by resource id |
| **The Tolgee Platform** (web app or REST API) | Create keys on the platform, `tolgee pull` generates `values-xx/strings.xml` | Create keys on the platform, the Content Delivery serves JSON, the app reads by key name |

The **column** decides whether you install the SDK. The **row** decides only how keys reach Tolgee, and you can change
it later without touching app code.

Choosing bundled? You do not need Tolgee Android SDK at all. The whole workflow is two Tolgee CLI commands, run
from the app module:

```bash
tolgee push   # send res/values/strings.xml to the platform
tolgee pull   # write the translations back before a release
```

The [Tolgee CLI push and pull](/tolgee-cli/push-pull-strings) page covers the configuration. Everything below covers
the over-the-air column.

## Prepare the Tolgee Platform first

Every guide starts from the same three things. Prepare them once per project in the Tolgee Platform; the
[Content Delivery guide](/android-sdk/content-delivery) explains each in detail.

1. **A project with your keys.** Either install the [Tolgee CLI](/tolgee-cli/installation) and push
   `res/values/strings.xml` with `format: "ANDROID_XML"`, or create the keys on the platform through the web app or
   the REST API. Key names must equal the resource entry
   names the app looks up.
2. **A Content Delivery in the "Android SDK" format.** It publishes one JSON file per language at a public URL prefix.
   Tolgee Android SDK reads JSON only; a delivery in another format produces an app that silently shows bundled text.
3. **The URL prefix and the list of published languages.** Both go into `Tolgee.init` in the Application class.

## Plan your time

With the three items above ready, the installation guides take about fifteen minutes each. The two
[starter apps](https://github.com/tolgee/tolgee-mobile-kotlin-sdk/tree/master/starters) go from clone to a
translation arriving over the air in under thirty minutes, including the platform steps, and their README is the
playbook the guides follow.
