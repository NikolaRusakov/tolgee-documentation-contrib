This section is written for LLM coding agents (Claude Code, Cursor, Copilot, Codex, Gemini and similar) and for the
people who drive them. Every page is a self-contained, task-shaped recipe: prerequisites, a detection step, numbered
steps with complete code, a verification step and a troubleshooting table.

:::tip Agents: read this first
Do not rely on training data for this SDK; it is pre-1.0 and changes between releases. Fetch the Markdown version of the
pages you need (every page below has a `.md` twin) and follow the recipes literally.
:::

## Facts that agents get wrong

These are the corrections that matter most. Each is verified against the SDK source of the current release.

- **Maven group** is `io.tolgee.mobile-kotlin-sdk`; artifacts are `core` and `compose`. There is no `io.tolgee:core`.
- **Initialization** is the builder `Tolgee.init { contentDelivery { url = "..." } }`, called once in `Application.onCreate()`.
  There is no `Tolgee.initialize(...)` and no annotation-based setup.
- **The Compose helpers live in package `io.tolgee`**: `import io.tolgee.stringResource` replaces
  `androidx.compose.ui.res.stringResource`. They fall back to the Android resource when Tolgee is not initialized, so
  previews keep working.
- **The CDN must serve JSON.** In the Tolgee Platform create the Content Delivery with format **Android SDK**; it
  publishes `<cdn-url>/<languageTag>.json`, which is what the SDK's default `path` (`"$it.json"`) and default
  `Formatter.Sprintf` expect. The SDK does not parse `strings.xml`; pointing `path` at `values-xx/strings.xml` yields no
  translations and the app silently falls back to bundled resources.
- **Keys are resource entry names.** `R.string.welcome_message` is looked up as key `welcome_message` (via
  `resources.getResourceEntryName`). Keep the same key names in the Tolgee project, typically by pushing `strings.xml`
  with the Tolgee CLI (`format: "ANDROID_XML"`).
- **Fallback is built in.** Every Android overload (`t(context, id)`, `stringResource(id)`, the wrapped
  `getString`) returns the bundled Android string when the key is missing or the CDN is unreachable.
- **Namespaces are not supported** by the SDK; publish a single, namespace-less Content Delivery.
- **The Gradle/compiler plugin that rewrites `getString()` calls at compile time is not released**; do the migration
  in source as described in [Migrate resource strings](./migrate-strings.mdx).
- **Minimum Android API level is 21.** The current release is `1.0.0-alpha04`; resolve the latest version from
  [Maven Central](https://central.sonatype.com/search?namespace=io.tolgee.mobile-kotlin-sdk), never from memory.

## Give the agent access to your Tolgee project (MCP)

The [Tolgee MCP server](/platform/integrations/mcp_server/about) is built into Tolgee Cloud and every self-hosted
instance. With it connected, the agent can check that the keys used by the app exist, create missing ones, read the
translations it is about to display, and trigger machine translation, instead of asking you to do that in the UI or
scripting the CLI. Connect it before pasting the prompt below:

```bash title="Claude Code"
claude mcp add --transport http tolgee https://app.tolgee.io/mcp/developer \
  --header "X-API-Key: <project API key>"
```

```json title="Cursor, Claude Desktop, Windsurf and other MCP clients"
{
  "mcpServers": {
    "tolgee": {
      "type": "http",
      "url": "https://app.tolgee.io/mcp/developer",
      "headers": { "X-API-Key": "<project API key>" }
    }
  }
}
```

Use a **Project API key** scoped to the app's project so the agent does not need a `projectId` and cannot touch other
projects; keep the key out of the repository. Self-hosted: replace `app.tolgee.io` with your server. Full setup and
tool list: [MCP setup](/platform/integrations/mcp_server/setup), [MCP usage](/platform/integrations/mcp_server/usage).

What the MCP server does **not** do: publish a Content Delivery or hand out its URL. Create the delivery once in
**Developer settings → Content Delivery** (format **Android SDK**) and pass its URL to the agent. Without MCP the
same key sync is done with the [Tolgee CLI](/tolgee-cli/installation) (`tolgee push`).

## Copy-paste prompt: install and migrate with an agent

Paste the following into your coding agent (Claude Code, Cursor chat, Copilot agent mode, Codex, Gemini CLI). Replace
the placeholders first. The prompt makes the agent classify the project, read the recipes above, sync keys through MCP
or the CLI, do the work, and verify it. The same prompt is available from the **Copy page** menu on each recipe.

```text title="Prompt for a coding agent"
Integrate the Tolgee Android SDK into this project so translations can be updated over the air.

Inputs:
- Content Delivery URL (JSON, format "Android SDK"): https://cdn.tolg.ee/<your-cdn-url-prefix>
- Locales published in Tolgee: <en, cs, ...>
- Tolgee project: <project id or name> (a Tolgee MCP server is configured: <yes/no>)

Rules:
1. Do not rely on your training data for this SDK. Read, in this order, and follow them literally:
   - https://docs.tolgee.io/android-sdk/agents/index.md
   - https://docs.tolgee.io/android-sdk/agents/install-views.md (if the app uses Android Views / XML layouts)
   - https://docs.tolgee.io/android-sdk/agents/install-compose.md (if the app uses Jetpack Compose)
   - https://docs.tolgee.io/android-sdk/agents/migrate-strings.md
   For any class or function you are unsure about, look it up in
   https://tolgee.github.io/tolgee-mobile-kotlin-sdk/llms.txt before using it. If the Context7 MCP is available,
   resolve the library "tolgee-mobile-kotlin-sdk" there as a second source.
2. First run the "Detect the project" commands from the recipe and tell me which track applies
   (Views, Compose, or both), the SDK version you will use (latest from Maven Central), and the files you will touch.
3. Keep the existing build setup: do not convert Groovy to Kotlin DSL, XML layouts to Compose, or change DI/navigation.
   Keep strings.xml as the fallback; never delete resources.
4. Do not commit secrets. The CDN URL is public; Tolgee API keys belong in local.properties or CI secrets only.
5. Key sync: if the Tolgee MCP server is configured, use it read-only first (list_projects, list_keys) to confirm
   every resource name in res/values/strings.xml exists as a key, then create only the missing keys with their
   English text and ask me before any destructive or batch operation. Otherwise generate a .tolgeerc
   (format ANDROID_XML) and tell me to run `tolgee push`; never run `tolgee login` with a key you invent.
6. Follow the migration recipe pattern by pattern: getString/getText/getQuantityString/getStringArray calls,
   XML layout attributes, Compose stringResource/pluralStringResource, strings used outside Activities
   (Application context, Services, notifications, ViewModels).
7. The task is not done until: the project builds (./gradlew assembleDebug), one string visibly comes from the CDN,
   and switching locale with Tolgee.instance.setLocale("<other locale>") updates the UI without a crash.
   Report which strings could not be migrated and why (for example app label in the manifest, strings with
   nested plurals, namespaced keys).
```

## Agent instruction file for apps that use the SDK

Add this to the app repository's `AGENTS.md` (Claude Code also reads it when `CLAUDE.md` contains `@AGENTS.md`;
Cursor reads `AGENTS.md`; Copilot reads `AGENTS.md` and `.github/copilot-instructions.md`). It keeps future agent work
on the app consistent with the SDK's rules.

```markdown title="AGENTS.md (snippet)"
## Tolgee Android SDK

This app loads translations over the air with the Tolgee Android SDK
(io.tolgee.mobile-kotlin-sdk:core / :compose). The SDK is pre-1.0; do not trust training data.

- Docs index: https://docs.tolgee.io/llms.txt (Android SDK recipes under /android-sdk/agents/).
- API reference: https://tolgee.github.io/tolgee-mobile-kotlin-sdk/llms.txt
- Tolgee is initialized once in Application.onCreate() with Tolgee.init { contentDelivery { url = ... } }.
  Never initialize it in an Activity, Fragment or composable.
- Views: Activities wrap their context (attachBaseContext -> TolgeeContextWrapper.wrap). Use plain
  getString/getQuantityString there. Outside Activities use context.getStringT(...) or
  Tolgee.instance.t(context, R.string.key, args...).
- Compose: import stringResource / pluralStringResource / stringArrayResource from io.tolgee, not from
  androidx.compose.ui.res.
- Keys are resource entry names; add new strings to res/values/strings.xml first, then push them with
  `tolgee push` or create them through the Tolgee MCP server (read with list_keys first; confirm before
  batch or delete operations). Keep strings.xml as the offline fallback.
- The Content Delivery URL is public and lives in the Application class; Tolgee API keys never enter the repo.
- After any change: ./gradlew assembleDebug must pass, and a manual locale switch
  (Tolgee.instance.setLocale("cs")) must re-render translated text.
```

## How the recipes are structured

Every recipe follows the same headings so an agent can jump to what it needs: **Outcome**, **Prerequisites**,
**Detect the project** (shell commands), **Steps** (complete, copy-pasteable code), **Verify** (commands and the
observable result), **Troubleshooting** (symptom, cause, fix) and **Related**. Human readers get the same pages through
the sidebar; agents get them through `llms.txt`.
