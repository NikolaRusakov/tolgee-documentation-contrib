Tolgee Android SDK is a Kotlin library that adds over the air translation updates to Android apps built with Views or
Jetpack Compose. You keep your `strings.xml`, push the keys to the Tolgee Platform, and initialize Tolgee Android SDK
with a Content Delivery URL. The app then loads translations from the Tolgee CDN at runtime, switches language without
a restart, and falls back to the bundled Android resources when it is offline.

## What does Tolgee Android SDK do?

Tolgee Android SDK replaces the moment a translation is decided. Without it, the text of `R.string.welcome_message`
is fixed when the APK is built. With it, the same resource id is looked up by its name (`welcome_message`) in a JSON
file that the Tolgee CDN serves for the current language. A translator fixes a typo in the Tolgee Platform, the
Content Delivery publishes, and every installed app shows the correction on its next start. No release, no store
review.

- **Over the air updates.** Translations come from the Tolgee Content Delivery, a CDN with one JSON file per language.
- **Same resource ids.** `getString(R.string.key)`, layout attributes and Compose `stringResource(R.string.key)` keep
  working; the key name is the resource entry name.
- **Offline by default.** The last downloaded translations are cached on the device. If the cache is empty, the SDK
  returns the bundled string. The app never shows a blank.
- **Language switch at runtime.** `setLocale("cs")` changes the language for the whole app without recreating
  Activities. Views and composables that read through Tolgee update on their own.
- **Two UI toolkits, one SDK.** The `core` artifact serves Android Views, the `compose` artifact adds Jetpack Compose
  helpers and includes `core`.

## How does a translation get from Tolgee to the screen?

The flow has four stops, and each has its own page in these docs.

1. **Your `strings.xml` is the source of keys.** You push it to the Tolgee Platform with the Tolgee CLI
   (`format: "ANDROID_XML"`). Translators and machine translation work on the platform.
2. **A Content Delivery publishes the translations.** Create it in the Tolgee Platform with format **Android SDK**. It
   produces `https://cdn.tolg.ee/your-cdn-url-prefix/<language>.json` for every published language. The
   [Content Delivery guide](/android-sdk/content-delivery) covers this step, including the one format mistake that
   silently disables everything.
3. **The app initializes Tolgee Android SDK once**, in `Application.onCreate()`, with that URL and a persistent cache.
4. **UI code reads strings as before.** In Views, a context wrapper routes `getString` and layout inflation through
   Tolgee. In Compose, three imports from `io.tolgee` replace the `androidx.compose.ui.res` helpers.

## Which artifact do I need?

| Your UI | Artifact | Start here |
|---|---|---|
| Activities, Fragments, XML layouts, ViewModel | `io.tolgee.mobile-kotlin-sdk:core` | [Tolgee with Android Views](/android-sdk/integrations/android-views) |
| Jetpack Compose or Compose Multiplatform | `io.tolgee.mobile-kotlin-sdk:compose` (includes `core`) | [Tolgee with Jetpack Compose](/android-sdk/integrations/jetpack-compose) |
| Both in one app | `compose` | Follow both guides; the Application setup is shared |

The Gradle plugin published under the same group configures a compiler plugin that is not released yet. Do not add
it to an app.

## What are the requirements?

- Android API level 21 or newer.
- Kotlin. The examples use the Gradle Kotlin DSL; the Groovy DSL works with the same coordinates.
- A Tolgee account, on [Tolgee Cloud](https://app.tolgee.io) or a self-hosted instance. Tolgee Android SDK only needs
  the public Content Delivery URL at runtime; API keys stay with the Tolgee CLI.
- Resolve the current SDK version on
  [Maven Central](https://central.sonatype.com/search?namespace=io.tolgee.mobile-kotlin-sdk). The SDK is pre-1.0 and
  the API can change between releases.

## Where can I see a working app?

Two starter apps in the SDK repository show the complete integration in about ten files each and are built on every
commit. Every code block in these docs is a file from one of them.

- [Android Views starter](https://github.com/tolgee/tolgee-mobile-kotlin-sdk/tree/master/starters/android-views):
  Activity, ViewModel, XML layouts, a locale switch, plurals and arrays.
- [Jetpack Compose starter](https://github.com/tolgee/tolgee-mobile-kotlin-sdk/tree/master/starters/jetpack-compose):
  the same screen in Compose with Material 3.

Larger demo apps, including Compose Multiplatform, live in the
[demo folder](https://github.com/tolgee/tolgee-mobile-kotlin-sdk/tree/master/demo) of the same repository.
