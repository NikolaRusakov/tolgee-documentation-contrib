Tolgee Android SDK changes the language of an Android Views app at runtime with one call, `setLocale`, followed by a
`preload` that fetches the new translations. Activities do not need to be recreated: `changeFlow` emits when the data
arrives, `retranslate` re-applies inflated layouts, and views bound with `tFlow` update on their own. This page is for
anyone adding a language switch to a Views screen.

## Switch the language

`setLocale` accepts a BCP 47 tag or a `java.util.Locale`. It only updates the locale; `preload` loads the translations
for it, cache first, then CDN. The demo wires each language button to the pair of calls, where `tolgee` is
`Tolgee.instance`.

```kotlin title="MainActivity.kt" file=<rootDir>/android-sdk/_snippets/views-switch-language.kt
```

The language is process-wide and not persisted by Tolgee Android SDK. If the app should remember it, store the tag
in your preferences and pass it to `Tolgee.init` with `locale("cs")` on the next start.

## React to the change

The `changeFlow` collector from [Installation](/android-sdk/integrations/android-views/installation) calls `retranslate`,
so layouts update in place after a switch. Text you set from code, such as the title or strings with arguments, is set
again inside the same collector, or kept current with `tFlow` as described on the
[Translating](/android-sdk/integrations/android-views/translating) page. For code that cannot use coroutines,
`ChangeListener` is the callback form; it runs on the main thread.

```kotlin
class LegacyActivity : Activity(), Tolgee.ChangeListener {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        Tolgee.instance.addChangeListener(this)
    }
    override fun onDestroy() {
        Tolgee.instance.removeChangeListener(this)
        super.onDestroy()
    }
    override fun onTranslationsChanged() = recreate()
}
```

## Choose the languages to offer

The languages published in the Content Delivery. Tolgee Android SDK learns them from `availableLocaleTags` in
`Tolgee.init`, or from the `manifest.json` file if the delivery serves one. `availableLocales` on the instance returns
the list after the first `preload`, and `null` before it.

```kotlin
val tags = Tolgee.instance.availableLocaleTags // for example [en, cs, fr, sv]
val current = Tolgee.instance.getLocale()
```

## Understand language fallback

Tolgee Android SDK resolves a requested locale progressively: `zh-Hans-CN` falls back to `zh-Hans`, then to `zh`, and
finally to `defaultLanguage` from `Tolgee.init`. A device set to `en-US` therefore receives the `en` translations
without any configuration. When a key is missing in the resolved language, the bundled Android resource for the
device configuration is returned, which is why keeping `values-xx/strings.xml` in the app still matters. The rules
and where the list of published languages comes from are on [Language and fallback](/android-sdk/language).
