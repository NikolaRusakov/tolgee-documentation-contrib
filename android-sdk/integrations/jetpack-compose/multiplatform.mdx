Tolgee Android SDK is a Kotlin Multiplatform library, and its `compose` artifact works in Compose Multiplatform
projects on Android, JVM desktop, iOS, macOS, JavaScript and Wasm. You add the artifact to `commonMain`, keep your
strings in `composeResources`, push them to Tolgee in the `COMPOSE_XML` format, and use the same `stringResource`
helpers with `Res.string` objects. This page is for anyone taking the Android integration to a shared Compose UI; it
lists the steps and the three things that differ from a plain Android app.

## Check supported platforms

The `compose` artifact publishes `androidTarget`, `jvm`, `iosX64`, `iosArm64`, `iosSimulatorArm64`, `macosX64`,
`macosArm64`, `js` and `wasmJs`. The `core` artifact it depends on targets more (tvOS, watchOS, Linux, Windows,
Android Native) for non-Compose use. Resource-id overloads, `TolgeeContextWrapper` and `retranslate` exist on Android
only; everything below is common code.

## Add the dependency

```toml title="gradle/libs.versions.toml"
[versions]
tolgee = "<latest-version>" # https://central.sonatype.com/search?namespace=io.tolgee.mobile-kotlin-sdk

[libraries]
tolgee-compose = { group = "io.tolgee.mobile-kotlin-sdk", name = "compose", version.ref = "tolgee" }
```

```kotlin title="composeApp/build.gradle.kts"
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation(compose.components.resources)
            implementation(libs.tolgee.compose)
        }
    }
}

compose.resources {
    generateResClass = auto
}
```

## Push strings to Tolgee

Compose Multiplatform keeps strings in `composeResources/values*/strings.xml` and generates `Res.string.<name>`
objects. Tolgee Android SDK looks a resource up by that name, so push the files in the `COMPOSE_XML` format and the
keys match without mapping:

```json title=".tolgeerc" file=<rootDir>/android-sdk/_snippets/mp-tolgeerc.json
```

Create the Content Delivery in the **Android SDK** format, as for Android; it publishes the same `<language>.json`
files with Android placeholders. The [Content Delivery guide](/android-sdk/content-delivery) covers the format rule and
the curl check.

## Initialize Tolgee

Put the configuration in one common function and call it from each platform entry point before the first composition:
`Application.onCreate()` on Android, `main()` on desktop, the app delegate or the SwiftUI `App` initializer on iOS.

```kotlin title="commonMain/Setup.kt" file=<rootDir>/android-sdk/_snippets/mp-setup.kt
```

This is the minimum. Add `availableLocaleTags(...)` and `defaultLanguage(...)` to enable
[language fallback](/android-sdk/language), and a `storage` provider for a persistent cache, as in the
[Content Delivery guide](/android-sdk/content-delivery#configure-path-locales-and-storage).
## Read translations in shared composables

The same helpers as on Android, imported from `io.tolgee`, with `Res` objects instead of `R` ids:

```kotlin title="commonMain/App.kt" file=<rootDir>/android-sdk/_snippets/mp-app.kt
```

The helpers recompose when the language changes and fall back to the Compose resource when Tolgee is not initialized,
so previews and tests behave as before.

## Note the differences from Android

1. **No persistent cache is provided outside Android.** `storage` is `null` on every platform unless you set it, so
   desktop, iOS and web re-download on every start and show bundled text offline. Implement the two-method
   `TolgeeStorageProvider` interface per platform; the JVM example is in
   [Loading and caching](/android-sdk/caching#set-up-persistent-storage). Android keeps
   `TolgeeStorageProviderAndroid`.
2. **No context wrapper, no `retranslate`.** Those work on Android `Resources` and `LayoutInflater`. In shared code
   every string goes through the composables or `tFlow`, which is what a Compose UI does anyway.
3. **Network permissions are platform concerns.** Android needs the network security config and the internet
   permission from the [installation guide](/android-sdk/integrations/jetpack-compose/installation); desktop and iOS
   need nothing; a browser target needs the CDN to answer with CORS headers, which the Tolgee CDN does.

## Switch and observe the language

`setLocale` accepts a language tag or a Compose `Locale`, and the helpers recompose on their own. To show the active
language, map `changeFlow` to `getLocale()` and collect it as state; the same code runs on every target.

```kotlin
@Composable
fun LanguageMenu() {
    val tolgee = Tolgee.instance
    val active by tolgee.changeFlow.map { tolgee.getLocale() }.collectAsState(initial = tolgee.getLocale())
    Row {
        (tolgee.availableLocaleTags ?: listOf("en")).forEach { tag ->
            Button(onClick = { tolgee.setLocale(tag) }, enabled = active.language != tag) { Text(tag) }
        }
    }
}
```

The language is not persisted by the SDK; store the tag with your platform's settings mechanism and pass it to
`locale(tag)` in `Tolgee.init` on the next start.

## Verify the setup

1. `./gradlew :composeApp:run` (desktop) shows the bundled text, then the translation from the Content Delivery.
2. Tap the language button: every text rendered through the helpers recomposes.
3. `./gradlew :composeApp:assembleDebug` and the iOS build succeed with the same shared code.

The [Compose Multiplatform demo](https://github.com/tolgee/tolgee-mobile-kotlin-sdk/tree/master/demo/multiplatform-compose)
in the SDK repository is the reference for this page.
