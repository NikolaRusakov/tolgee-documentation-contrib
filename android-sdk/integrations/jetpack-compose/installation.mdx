Tolgee Android SDK adds over the air translation updates to Android apps built with Jetpack Compose. You add one Gradle
dependency, allow the Tolgee CDN in your network security config, initialize Tolgee in your Application class with your
Content Delivery URL, and import `stringResource` from `io.tolgee` instead of `androidx.compose.ui.res`. After that your
composables show translations from the Tolgee CDN, recompose on a language switch, and fall back to bundled resources
when offline.

## Add the Tolgee dependency

For Compose you need the `compose` artifact from the group `io.tolgee.mobile-kotlin-sdk`; it already contains `core`.
Take the version from
[Maven Central](https://central.sonatype.com/search?namespace=io.tolgee.mobile-kotlin-sdk); the SDK is pre-1.0 and
releases often.

```toml title="gradle/libs.versions.toml"
[versions]
tolgee = "<latest-version>" # https://central.sonatype.com/search?namespace=io.tolgee.mobile-kotlin-sdk

[libraries]
tolgee-compose = { group = "io.tolgee.mobile-kotlin-sdk", name = "compose", version.ref = "tolgee" }
```

```kotlin title="app/build.gradle.kts"
android {
    buildFeatures {
        compose = true
        buildConfig = true // BuildConfig.VERSION_CODE keys the on-device translation cache
    }
}

dependencies {
    implementation(libs.tolgee.compose)
}
```

Compose Multiplatform: add the same library to the `commonMain` dependencies of the shared module. Sync the project;
the build should stay green.

## Initialize Tolgee in the Application class

<TolgeeInit />

Never call `Tolgee.init` inside a composable. In a Compose Multiplatform project put the same block in a function in
`commonMain` and call it from each platform entry point; `TolgeeStorageProviderAndroid` is Android-only, so provide a
`TolgeeStorageProvider` implementation per platform if you want a persistent cache there.

## Read strings in composables

Replace three imports. The Tolgee helpers have the same signatures as the Compose originals, so no call site changes.
The demo app shows a static string and a string with a parameter:

```diff
- import androidx.compose.ui.res.stringResource
- import androidx.compose.ui.res.pluralStringResource
- import androidx.compose.ui.res.stringArrayResource
+ import io.tolgee.stringResource
+ import io.tolgee.pluralStringResource
+ import io.tolgee.stringArrayResource
```

```kotlin title="MainActivity.kt" file=<rootDir>/android-sdk/_snippets/compose-basic-text.kt
```

```kotlin title="MainActivity.kt" file=<rootDir>/android-sdk/_snippets/compose-parametrized-text.kt
```

Each helper collects `tolgee.tFlow(...)` as state with the bundled resource as the initial value. The first frame shows
the fallback and the composable recomposes when the cache or the CDN answers. When `Tolgee` is not initialized, in
`@Preview` functions and unit tests, the helper returns the plain Compose resource. Compose Multiplatform uses the same
functions with `Res.string.description` and `Res.plurals.plr_test_placeholder_2`.

## Verify the installation

1. Build the app:

   ```bash
   ./gradlew :app:assembleDebug
   ```

   If the compiler reports an ambiguous `stringResource`, a file still imports the `androidx.compose.ui.res` version
   next to the `io.tolgee` one. Keep only the Tolgee import.
2. Run it. The first frame shows the bundled text; within a second the text from the Content Delivery replaces it.
   Change one translation in the Tolgee Platform, wait for the delivery to publish, and reopen the screen. The CDN
   edge caches for up to fifteen minutes.
3. Add a temporary button that calls `Tolgee.instance.setLocale("cs")` with any published language. Every text
   rendered by the Tolgee helpers recomposes; no `preload` call is needed in Compose.
4. Open a `@Preview`. It still renders, through the fallback.

Done means: the build is green, one string visibly came from the CDN, a language switch recomposed the screen, and
previews are unaffected.

## Add a new string

Add it to `res/values/strings.xml` first, because the resource id is what the composable references and what the
fallback shows. Push it with `tolgee push`, translate it in the Tolgee Platform, and the Content Delivery publishes it.
The composable that reads the string recomposes with the translation the next time the app loads the language, and
shows the bundled text until then. No code beyond the `stringResource` call changes, and no release is needed for the
translated versions to reach users.

## Compare the helper with the Compose original

`androidx.compose.ui.res.stringResource` reads the resource once from the current configuration and never changes
until the Activity is recreated. `io.tolgee.stringResource` returns the same value on the first frame, then collects
`tFlow` for the key: it emits the cached or downloaded translation, and emits again on every `setLocale` and every
published change. The two functions have identical signatures, which is why the migration is an import change, and
the Tolgee version delegates to the original when no `Tolgee` instance exists.

## Fix common problems

Text never changes from the bundled value: `Tolgee.init` is missing or ran after the first composition, or the Content
Delivery prefix is wrong. `Unresolved reference: stringResource`: the old import was removed but the Tolgee import not
added. A plural shows the wrong form: the count was passed only as a format argument, not as `quantity`. The
[troubleshooting page](/android-sdk/troubleshooting) has the fix for each.
